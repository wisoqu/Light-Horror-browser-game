# Работа в параллель: как не столкнуться

Два агента могут спокойно работать над этим репозиторием одновременно, если
разделить **файлы**, а не «задачи». Правило одно и оно жёсткое:

> Каждый файл имеет ровно одного владельца. Второй агент не редактирует чужие
> файлы — даже если видит там опечатку. Вместо этого он пишет об этом в
> `docs/PARALLEL-NOTES.md` (свой файл, только дописывать в конец).

## 2. Контракты, которые нельзя ломать

Агент B переписывает `audio.js` как хочет, но снаружи обязаны остаться:

```js
class GameAudio {
  constructor()
  init()            // создаёт AudioContext, вешает шины
  resume()
  setMaster(muted)  // M
  update(dt, { panic, enemyDist, enemyLos, hunted })
  // одноразовые события:
  step(sprint, crouch) · breath() · gasp() · heartbeat(i) · whisper()
  stinger() · thud() · fuseFix() · spark() · pickup() · paper()
  locker(open) · flicker() · doorRattle() · scream() · winChime()
  tone(freq, dur, opts) · noise(dur, opts)   // используются scares.js
}
```

Ограничения по звуку:

- **никаких файлов**: только осцилляторы, шум и фильтры (иначе проект теряет
  офлайн-запуск);
- общий выход должен оставаться в пределах −3 дБFS: сейчас пики держатся
  около 0,3–0,4, и это осознанно;
- `update()` вызывается каждый кадр — без создания узлов, если значение не
  изменилось;
- при `document.hidden` звук глушится (сейчас это делает `main.js`, не ломать).

## 3. Порядок работы, чтобы не мешать друг другу

1. Каждый работает **в своей ветке** и открывает свой PR. Ветку этой сессии
   (`arena/...-light-horror-browser-game`) второй агент не трогает.
2. Коммиты — маленькие и по файлам своего набора. `git status` перед коммитом:
   если в списке чужой файл — не коммитить его.
3. Мы не правим один и тот же файл даже «на секунду»: merge-конфликт в
   `world.js` стоит дороже, чем любая правка.
4. Слияние — сначала PR агента A (он меняет структуру сцены), потом PR агента B
   (он навешивает звук и CI поверх). Если B успел раньше — конфликтов всё равно
   не будет, наборы файлов не пересекаются.
5. Если B нужна правка в файле A — это **запрос**, а не действие:
   строка в `docs/PARALLEL-NOTES.md` в формате
   `[файл] что не так → что предлагаю`. Агент A читает этот файл перед каждым
   своим коммитом.

## 4. Проверки перед каждым PR

```bash
node --check src/*.js          # синтаксис (для каждого файла)
node --test tests/map42.test.mjs
node tools/validate-world.mjs  # если файл есть в ветке
```

Что должно остаться верным после любых изменений:

- все 327 проходимых клеток достижимы и для игрока, и для дежурной;
- старт `{19, 14}` свободен, ни один якорь не замурован в стену;
- `node --test tests/map42.test.mjs` — 11/11;
- игра открывается с `python3 -m http.server` без ошибок в консоли.

## 5. Чего делать нельзя (общее)

- менять правила игры: слух, зрение, скорость, батарею, панику, условия
  смерти и победы;
- добавлять внешние ассеты и CDN — проект обязан работать офлайн;
- переименовывать экспорты и публичные методы без согласования;
- коммитить `node_modules/` (это симлинк на песочницу, он в `.gitignore`).
